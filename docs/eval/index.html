What we got wrong, and what it taught

  • An eval bug invented a problem Week 3
    "RBI search finds the right clause 7/14" was a scoring bug (scored after de-duplication). A second script scoring the same thing exposed it.
  • Slow answers were the network, not the code Week 3
    12-31 s answers were Qdrant Cloud over a poor connection; found only after timing each stage.
  • One shared index gave a wrong answer Week 3-4
    A LAP question got the home-loan LTV (75% instead of 65%). Fixed by a product filter and product-scoped RBI clauses (ADR-009, ADR-012).
  • An audit log must store the output Week 4
    The log kept the question but not the answer text, which is what a reviewer needs when an answer is wrong; since Week 4 it stores both.
  • A one-run move of +-2 is noise Week 4
    Model-scored metrics move by 1-2 between identical runs; compare runs, not single numbers.
  • A strict check made answers worse Week 5
    "Cite every source you name" made retries name unretrieved sources; two correct answers were refused. Block only what is actually wrong (ADR-017).
  • Asking beats guessing Week 5
    A free, rule-based "which product?" took product accuracy from 37/47 to 52/52 when the product came from the question text (ADR-018).
  • The metric can't see the user's screen Week 5
    About 75 of 975 citation links highlighted the wrong paragraph, invisible to every score; found by checking RBI's page and clicking (ADR-019).
  • Evaluate the test set too Week 5
    p17, c03, c10 "failures" were golden-set or scorer errors, not system errors.
  • A closed list needs saying Week 6
    "Can an HUF apply?" was hedged until the prompt said an eligibility list is complete; a banker's review set the expected answer (v09, answer-v6).
  • The builder's test set shares the builder's blind spots Week 6
    Name masking: 100% on the set its rules were built on, 95% on held-out questions; a banker's own 7 questions found a case neither set had (ADR-021).
